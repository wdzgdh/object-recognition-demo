# 离线评测（B6）

`tools/evaluate.py` 用一批**标注好的图片**量化系统表现，回答四个问题：

1. 认识的物体认得准吗？（Top-1 / Top-3）
2. 不认识的物体会不会硬说成认识的？（未知召回 / 误接收率 FAR）
3. 会把认识的物体说成未知吗？（误拒率 FRR）
4. 阈值到底该定多少？（阈值扫描）

指标实现在 `tools/metrics.py`，是纯 Python 函数，`tests/test_metrics.py` 覆盖了全部分支，
**不需要 torch / numpy** 就能跑。

---

## 1. 准备数据

```
data/
├── test/                 ← 已知样本，子目录名 = 真实类别，必须与特征库里的名字一致
│   ├── 水杯/  1.jpg 2.jpg ...
│   ├── 马/    1.jpg 2.jpg ...
│   └── 手/    ...
├── unknown/              ← 未注册过的东西，用来测"会不会乱认"
│   ├── 台灯.jpg
│   └── 椅子.jpg
└── register/             ← 给 batch_register.py 用的注册图（和 test/ 不能是同一批）
```

**几条经验（直接决定评测结果可不可信）：**

| 要求 | 原因 |
| --- | --- |
| 每类 ≥ 20 张，至少 10 张来自**没参与注册**的拍摄 | 5 张就能算出 100%，但那是过拟合 |
| `test/` 的类别名与特征库里**逐字一致** | 不一致会被算成全错 |
| `unknown/` 放 10~30 张现场容易出现的其它东西 | 未知召回样本太少，FAR 一条样本就跳 10% |
| 已知 / 未知样本尽量混在同一批拍摄条件下 | 否则模型学到的其实是"背景亮度" |
| 注册图和测试图分两次拍（不同角度/光照） | 同一张图既注册又测试 = 自欺欺人 |

## 2. 跑一遍

```bash
# 先批量注册（如果还没注册）
python tools/batch_register.py --dir data/register

# 全量评测
python tools/evaluate.py

# 指定目录 / 开启 TTA / 快速冒烟（只跑前 30 张）
python tools/evaluate.py --test data/test --unknown data/unknown --out docs/eval --tta
python tools/evaluate.py --limit 30
```

命令行会打一张表：

```
评测样本：120 张（已知 90 / 未知 30）
Top-1 准确率     : 91.1%
Top-3 命中率     : 97.8%
未知召回率       : 86.7%   （越高越不会把陌生物体说成已知）
误接收率(FAR)    : 13.3%   （越低越好）
误拒率(FRR)      : 6.7%    （已知被说成未知，阈值过高的代价）

阈值扫描（挑阈值用）：
  阈值   Top1    未知召回  误接收   误拒
  0.70   93.3%   60.0%    40.0%   2.2%
  0.75   92.2%   73.3%    26.7%   4.4%
  0.80   91.1%   86.7%    13.3%   6.7%  ← 综合最佳
```

## 3. 产物怎么读

默认写到 `docs/eval/`（CSV 是 UTF-8-BOM，Excel 双击不乱码）：

| 文件 | 内容 | 用途 |
| --- | --- | --- |
| `report.csv` | 逐张明细：文件 / 真实 / 预测 / 最佳类 / 原始分 / 是否正确 / TopK | 挑出错的那些图，看是数据问题还是模型问题 |
| `summary.csv` | 汇总指标 + 每类样本数 | 贴进报告 |
| `confusion.csv` | 混淆矩阵，行=真实，列=预测 | 看哪两类老是混（比如"水杯"↔"保温杯"） |
| `threshold_sweep.csv` | 不同阈值下的四个指标 | 定阈值 |

`report.csv` 的 **`最佳类`** 列是"只按相似度选出的第一名"，和 `预测` 不同：
`预测` 已经过阈值判定，低于阈值会被写成「未知物体」。阈值扫描就靠 `原始分 + 最佳类` 重算，
所以 **`--from-report` 不重新提特征，几秒就能扫完**：

```bash
python tools/evaluate.py --from-report docs/eval/report.csv --thresholds 0.65,0.70,0.75,0.80,0.85
```

---

## 4. 怎么用结果定阈值

扫描表里挑的是 **Top-1 和未知召回的均衡点**（脚本会标 `← 综合最佳`），但真实取舍看场景：

- **演示 / 课堂**：怕"认错"，就把阈值往上调，宁可多显示几次「未知物体」。
- **自动分拣 / 需要少打扰**：怕"总说不知道"，就往下调，接受偶尔认错。

改完阈值记得同步 `object_recognition/config.py` 的 `THRESHOLD` 默认值（界面滑条上的改动只落盘到本机
`data/ui_state.json`，不进版本库）。

---

## 5. 注意

- 脚本**只读**特征库，不会修改任何注册数据；`--out` 目录不存在会自动创建。
- 单张图片读不了只计入"跳过"，不会中断整轮评测（末尾会列出跳过的文件）。
- 换机型/换摄像头后**必须重跑**：特征库和评测集都变了，旧数字没有参考价值。
- 生成的 CSV 默认不进版本库（见 `.gitignore`）；要存档基线就 `git add -f docs/eval/report.csv`。
